# Career Quest

Рабочая версия кейса трека Halyk Bank на HackAlem AI.

Заказчик: АО Народный Банк Казахстана. Кейс: Career Quest — платформа геймификации жизненного цикла сотрудника. Второй кейс трека, Voice Router, в этот репозиторий не входит. Кейсы оцениваются раздельно.

## Проблема

Сотрудник получает разрозненные HR-события без видимой связи с его развитием. Обучение проходится формально в день дедлайна. Добровольные активности собирают низкую явку, при этом бюджет на развитие персонала израсходован полностью.

## Что требует официальный кейс

Веб-приложение с AI-слоем. Ядро задачи — качество и объяснимость рекомендации, а не интерфейсная оболочка. Геймификация является надстройкой и не входит в обязательную часть.

Обязательно:

- Профиль сотрудника и карьерная траектория: роль, грейд, навыки, пройденные активности и доступные следующие шаги.
- AI-рекомендация 1–3 релевантных активностей.
- Объяснение минимум по трём факторам. В ТЗ названы грейд, разрывы по навыкам, история участия и требования следующего уровня.
- Обновление прогресса после отметки активности выполненной: сдвигаются прогресс по навыку и траектория.
- Простой HR-экран: какие навыки чаще проседают, у кого нет рекомендованного шага, участие по активностям.
- Загрузка дополнительных профилей и истории в формате датасета.

Жюри использует три проверочных профиля, одинаковых для всех команд. Они составлены так, чтобы однофакторное правило на них ошибалось. Пример из ТЗ: ниже всего Public Speaking, похожие активности пропущены трижды, а для следующего грейда критичен System Design. Рекомендация «бери минимальный навык» промахивается. На защите эти профили загружает жюри.

Задержка по ТЗ: отклик интерфейса до 2 секунд; AI-рекомендация до 10 секунд.

Приватность и безопасность по ТЗ: внутренний контур; данные о вовлечённости не видны другим сотрудникам без согласия; права сотрудника и HR разграничены.

ТЗ запрещает: рекомендацию по одному полю под видом AI; публичные рейтинги по результативности; механику вокруг обязательных процессов (пример — очки за таймшиты); реальные персональные данные. Принуждение названо главным предиктором провала таких программ. Должно быть видно, почему предложен шаг и как рассчитано продвижение. Проект должен запускаться одной командой.

Опциональные пункты ТЗ, не сделанные и не выбранные: внутренняя валюта, каталог вознаграждений, признание от коллег, менторские и командные механики, персональные вызовы, конструктор событий для HR, прогноз риска оттока, расширенный HR-дашборд, моделирование перехода на грейд, встраивание в мессенджер или календарь, мобильная адаптация, качественная локализация интерфейса на казахский и русский.

## Данные

Выданный датасет синтетический. По ТЗ его нельзя выносить за пределы хакатона. В этом репозитории его нет.

Локальный аудит датасета версии 1.0, дата среза `2026-10-01`:

- 60 навыков и 32 профиля ролей (8 ролей, грейды Junior / Middle / Senior / Lead)
- 200 сотрудников
- 40 событий
- 2 743 записи участия с `2024-10-01` по `2026-09-30` (24 месяца)

ТЗ говорит, что данные на английском и есть переводы на казахский и русский. Проверенные JSON- и CSV-записи на английском. Казахский и русский текст есть в README датасета. Это расхождение записано в `docs/PROJECT.md` и не разрешено.

README датасета говорит, что обязательные события не являются целью рекомендации. В файле истории после `completed` повторяются `EV_001`, `EV_002` и `EV_003`, помимо указанного исключения `EV_036`.

## Статус

Спецификация и исследование.

В этом репозитории ещё нет рекомендаций, профилей, HR-экрана, загрузки данных, разграничения прав и интерфейса. Стек, механизм аутентификации, модель данных, подход к рекомендациям, AI-провайдер и UX не выбраны.

Деплоя, живого демо и команды запуска пока нет.
